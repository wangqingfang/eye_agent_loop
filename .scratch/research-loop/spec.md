# 研究循环（干眼共病 AgentLoop）

## Problem Statement

我在支持孙勇教授申报「基于医工融合的多模态 AI 大模型的干眼症共病精准诊疗与药物研发」项目。手上只有一份《干眼共病模型数据字典 V1.0》（212 个候选字段，全部待映射），还没有真实患者数据。项目需要从共病、药物暴露、眼表检查等临床数据中找到值得干预的靶点和治疗方向，但靠人工在数据和中外文献之间来回比对，每一轮都要重新取数、查文献、写结论，效率低、难以追溯，而且多次检验同一份数据很容易把噪声当成发现。

## Solution

一个全自动运行的研究循环。每个研究轮次依次完成数据发现、文献检索、假设生成、审稿、登记与验证五个阶段：从探索集得到表型发现，结合 PubMed、Europe PMC、ClinicalTrials.gov 与 Open Targets 推导靶点假设，经审稿剔除站不住的假设，先登记再到验证集上检验，最后产出中文的轮次报告。多轮之后累积成一份连续的报告，列出所有有意义结论及其证据链。

真实数据到位前，研究循环在依据数据字典生成、带植入信号的合成数据上运行，同时用植入信号的找回情况衡量研究循环本身的质量。LLM 只接触汇总统计，所有患者级计算在本地完成。数据中一旦出现基因或组学字段，组学模块自动启用。

## User Stories

1. 作为研究者，我希望用一条命令启动一次研究循环，以便不需要逐步手动操作。
2. 作为研究者，我希望在启动时指定数据目录、最大轮数和 token 预算，以便控制运行范围和成本。
3. 作为研究者，我希望通过配置切换模型提供方和模型名，以便在 DeepSeek、千帆等 OpenAI 兼容服务之间更换而不改代码。
4. 作为研究者，我希望在没有真实数据时能依据数据字典生成合成数据，以便立即开始开发和试运行。
5. 作为研究者，我希望合成数据遵守数据字典的 0/1/NA 缺失值规则，以便研究循环从一开始就按真实约束处理缺失。
6. 作为研究者，我希望合成数据遵守以索引日期为锚点的时间规则，以便数据泄漏问题在合成阶段就能暴露。
7. 作为研究者，我希望合成数据中植入共识 A 级关联，以便确认研究循环能找回已知事实。
8. 作为研究者，我希望合成数据中植入若干共识未列出的新信号，以便确认研究循环有发现新东西的能力。
9. 作为研究者，我希望合成数据中包含一批与干眼无关的字段，以便衡量研究循环报告假信号的比例。
10. 作为研究者，我希望每次运行结束后看到植入信号的找回率和假信号数，以便判断研究循环是否可信。
11. 作为研究者，我希望合成数据默认覆盖 2 万名患者和 63 个 P0 字段，以便规模接近首轮真实抽取。
12. 作为研究者，我希望研究循环只接受一种数据格式（以英文变量名为列名的 CSV 或 Parquet 目录），以便合成数据与真实数据可以无缝替换。
13. 作为数据工程师，我希望有一个独立的映射脚本把医院交付的数据转换成该格式，以便研究循环本身不受医院库表差异影响。
14. 作为研究者，我希望研究开始时按患者一次性固定划分探索集和验证集，以便后续任何轮次都无法重新划分。
15. 作为研究者，我希望表型发现只在探索集上产生，以便验证集保持未被窥视。
16. 作为研究者，我希望每个靶点假设在检验前先登记且登记后不可修改，以便杜绝看了结果再改假设。
17. 作为研究者，我希望所有轮次的检验累计做 FDR 校正，以便多轮挖掘不会放大假阳性。
18. 作为研究者，我希望所有关联分析默认调整年龄、性别和索引日期前 365 天眼科就诊次数，以便控制混杂和检测偏倚。
19. 作为合规负责人，我希望 LLM 只能看到数据字典和汇总统计，以便患者级数据不离开本地。
20. 作为合规负责人，我希望任何样本数小于 10 的分组结果在送给 LLM 和写入报告前被抑制，以便避免小群体再识别。
21. 作为合规负责人，我希望 LLM 只能调用预置统计工具而不能执行自写代码，以便所有数据访问可审计、可复现。
22. 作为研究者，我希望统计工具至少包括描述统计、分层对比、logistic 回归、Cox 回归和倾向评分匹配，以便覆盖首轮研究所需的分析类型。
23. 作为研究者，我希望数据发现阶段从探索集中找出与干眼及其分型相关的共病、药物暴露和检查指标，以便得到本轮的表型发现。
24. 作为研究者，我希望文献检索阶段围绕本轮表型发现检索 PubMed、Europe PMC 和 ClinicalTrials.gov，以便获得中外最新研究证据。
25. 作为研究者，我希望文献检索阶段同时查询 Open Targets 的疾病-靶点和靶点-药物关联，以便「共病 → 通路 → 靶点」的推导有结构化证据支撑。
26. 作为研究者，我希望先读摘要，对排名靠前且开放获取的文献再读全文，以便在成本和深度之间取得平衡。
27. 作为研究者，我希望检索结果按 PMID 本地缓存，以便同一文献不重复下载、重跑结果一致。
28. 作为研究者，我希望假设生成阶段把表型发现与文献证据结合成靶点假设，并写明可在数据中检验的代理指标，以便每个假设都能回到数据验证。
29. 作为研究者，我希望每个靶点假设引用的 PMID 都必须来自本轮实际检索到的文献，否则被剔除并在报告中标注，以便杜绝编造文献。
30. 作为研究者，我希望审稿阶段由独立的 LLM 调用专门质疑候选假设，以便在消耗验证集之前剔除站不住的假设。
31. 作为研究者，我希望审稿意见和被剔除的理由写入报告，以便事后复核审稿是否过严或过松。
32. 作为研究者，我希望登记与验证阶段在验证集上检验已登记假设并给出效应量、置信区间和校正后 p 值，以便判断是否形成有意义结论。
33. 作为研究者，我希望有意义结论同时满足「验证集上 FDR 校正后显著」和「有文献支持或被明确标记为文献未见」，以便结论既可靠又标明新颖性。
34. 作为研究者，我希望下一轮基于此前所有轮次的结论和未解决问题继续深入，以便轮次之间形成递进而不是重复。
35. 作为研究者，我希望研究循环在跑满最大轮数（默认 5）时停止，以便运行有明确上限。
36. 作为研究者，我希望连续 2 轮没有新的有意义结论时提前停止，以便不浪费成本在没有进展的方向上。
37. 作为研究者，我希望 token 消耗达到预算时停止并保存当前进度，以便成本可控。
38. 作为研究者，我希望每个研究轮次结束时生成中文轮次报告，以便随时了解进展。
39. 作为研究者，我希望所有轮次报告累积在一份 HTML 报告中，按轮次追加章节，以便报告有连续性。
40. 作为研究者，我希望报告开头有进展区，用折线图展示各轮提出的假设数、验证通过数，以及主要结论的效应量和置信区间变化，以便一眼看出研究在推进还是停滞。
41. 作为研究者，我希望每轮章节包含本轮的数据表格、图表、结论及其证据链，以便单独阅读任何一轮也能理解。
42. 作为研究者，我希望报告中的文献保留英文原题和 PMID，正文结论用中文，以便既便于阅读又便于溯源。
43. 作为研究者，我希望报告可以双击直接在浏览器打开，以便不依赖额外软件。
44. 作为研究者，我希望能把报告导出为 Word，以便用于项目申报和汇报材料。
45. 作为研究者，我希望每次运行的划分结果、已登记假设、各阶段输入输出、文献缓存和 FDR 账本都保存在该次运行的目录里，以便完整追溯。
46. 作为研究者，我希望运行中断后能从最后一个完成的阶段继续，以便不必从头再跑。
47. 作为研究者，我希望在数据字典中声明「基因与组学」模块且数据中这些字段有值时，组学模块自动启用，以便拿到组学数据后无需改动研究循环。
48. 作为研究者，我希望组学模块未启用时研究循环行为完全不变，以便预留扩展不影响第一版。
49. 作为研究者，我希望运行记录不提交到 git，以便仓库不混入可能含敏感信息的中间产物。
50. 作为后续开发者，我希望模块命名和报告用语与项目术语表一致，以便代码、报告和讨论使用同一套语言。
51. 作为没有编程经验的研究者，我希望在技术同事一次性安装后，双击启动文件、按中文提示选择即可运行，无需使用终端，以便独立完成研究。
52. 作为没有编程经验的研究者，我希望 API Key 等设置写在可用记事本编辑的中文配置文件里，以便不必了解环境变量。
53. 作为没有编程经验的研究者，我希望有一份中文使用说明，解释报告中的统计数字、探索集与验证集、文献引用的含义，以便正确理解结论。
54. 作为没有编程经验的研究者，我希望出错时看到中文的可操作提示，以便知道是缺少 API Key、余额不足还是断网。

## Implementation Decisions

- **技术栈**：Python。模型通过 OpenAI 兼容协议接入并依赖原生 tool calling，默认 DeepSeek；提供方、模型名、base_url 与 API key 全部来自配置或环境变量，不写入代码。
- **使用者**：最终使用者没有编程经验。日常使用不依赖终端：通过双击启动文件和中文菜单运行，设置写在被 git 忽略、可用记事本编辑的中文配置文件中，常见错误给出中文可操作提示。安装由技术同事一次性完成。中文使用说明随代码维护，与实际行为保持一致。
- **整体形态**：研究循环不是自主 agent。每个研究轮次由代码按固定顺序编排五个阶段（数据发现 → 文献检索 → 假设生成 → 审稿 → 登记与验证），每个阶段只开放本阶段的工具，LLM 只在阶段内做判断（ADR 0004）。
- **模块划分**：
  - 数据字典加载：读取数据字典 Excel，提供字段定义、证据等级、P0/P1/P2 优先级、共病实体词典和衍生特征定义。
  - 合成数据生成：依据数据字典生成患者数据，支持声明植入信号（关联方向、强度、涉及字段）及无关字段；输出与真实数据相同的目录格式，并单独保存植入信号清单供评测使用，该清单对研究循环不可见。
  - 数据访问层：唯一能读取患者级数据的模块。负责加载数据目录、一次性划分并持久化探索集/验证集、对验证集实施访问门控（仅在登记与验证阶段、且仅针对已登记假设开放）。
  - 统计工具：描述统计、分层对比、logistic 回归、Cox 回归、倾向评分匹配。每个工具只返回汇总结果（样本量、效应量、置信区间、p 值），并在返回前抑制样本数小于 10 的分组。默认协变量为年龄、性别、索引日期前 365 天眼科就诊次数。工具以 tool calling 的 schema 暴露给 LLM（ADR 0001、0002）。
  - FDR 账本：跨轮次累计记录所有验证检验，统一做 FDR 校正，校正结果随每次新检验更新。
  - 外部来源接口：一个统一接口，背后接 PubMed、Europe PMC、ClinicalTrials.gov、Open Targets 四个适配器；结果按 PMID（或各来源的唯一 ID）本地缓存。先取摘要，排名前 k 且开放获取的再取全文。
  - LLM 接口：对 OpenAI 兼容客户端的薄封装，统一处理 tool calling、token 计数与预算检查。
  - 阶段实现：五个阶段各自定义输入、输出与可用工具。假设生成阶段输出的每个靶点假设包含：假设陈述、依据的表型发现、引用的 PMID/Open Targets 证据、在数据中检验所用的代理指标与分析方法。
  - 引用校验：在假设进入审稿前，剔除引用了本轮检索结果之外 PMID 的部分，并记录剔除原因。
  - 假设登记表：登记后的假设只读；验证结果以追加方式写入。
  - 运行编排：驱动轮次与阶段，判断停止条件（最大轮数默认 5；连续 2 轮无新有意义结论；token 预算耗尽），每个阶段完成后写检查点，支持从最后完成的阶段恢复。
  - 报告生成：读取运行目录生成单一 HTML 报告（图表内嵌、可离线打开），开头为进展区折线图，之后每轮一章；提供导出 Word 的能力。报告正文中文，文献保留英文原题与 PMID。
  - 组学模块：以接口形式预留。运行开始时，若数据字典声明了「基因与组学」模块且数据中对应字段有值，则在数据发现阶段额外启用组学分析并产出靶点假设；否则完全不参与。
- **数据契约**：研究循环只接受一个目录，其中每张表为 CSV 或 Parquet，列名为数据字典中的英文变量名；缺失值编码遵守 0/1/NA 规则；索引日期字段必须存在。医院数据通过独立的映射脚本转换为此格式，映射依据数据字典中的「数据库映射模板」，映射脚本不属于研究循环本身。
- **合规边界**：任何送入 LLM 的内容只能来自数据字典、统计工具的汇总返回值和外部来源的文献内容。数据访问层不向 LLM 接口暴露任何患者级对象（ADR 0001）。
- **防假阳性机制**：探索集/验证集按患者在研究开始时一次性划分并保存，之后不可重划；表型发现只用探索集；靶点假设先登记后检验；所有检验进入 FDR 账本累计校正（ADR 0003）。
- **有意义结论判定**：验证集上 FDR 校正后显著，且有文献支持或被明确标为文献未见。判定由代码依据检验结果和引用情况完成，而不是由 LLM 自行宣布。
- **运行目录内容**：配置快照、划分结果、各轮各阶段的输入输出、假设登记表、FDR 账本、文献缓存、token 用量、HTML 报告。运行目录整体排除在 git 之外。
- **评测**：在合成数据上运行时，运行结束后对照植入信号清单计算找回率和假信号数，并写入报告末尾的评测章节；真实数据运行时不生成此章节。

## Testing Decisions

- **好测试的标准**：只测外部可观察的行为（运行目录里的产物、报告内容、送给 LLM 的消息、工具返回值），不测内部函数调用顺序或私有结构。
- **主接缝：研究循环入口**。输入运行配置和数据目录，输出运行目录。LLM 接口替换为按剧本回复的假模型，外部来源接口替换为录制好的响应。在小规模合成数据上端到端跑完，断言：
  - 登记假设之前，数据访问层从未向任何阶段提供验证集数据。
  - 所有送入 LLM 的消息中不含患者级记录，不含样本数小于 10 的分组。
  - 引用了本轮检索结果之外 PMID 的假设部分被剔除，并在报告中标注。
  - 已登记假设在验证后保持不变。
  - 满足最大轮数、连续无进展、token 预算三种停止条件时分别正确停止。
  - 在任意阶段之后中断再恢复，最终运行目录和报告与不中断的运行一致。
  - 报告包含进展区和每轮一章，轮次连续。
  - 组学字段无值时组学模块不启用；有值时启用。
  - 合成数据上植入的强信号被找回，无关字段不被报告为有意义结论。
- **次接缝：统计工具层**。用已知效应量的生成数据直接调用各统计工具，断言效应量与置信区间落在预期范围、默认协变量被纳入、小样本分组被抑制、FDR 校正结果与标准实现一致。
- **不单独设接缝**：合成数据生成、报告渲染、各阶段实现均经由主接缝间接覆盖。
- **已有测试先例**：仓库中无可复用的测试先例，这是该项目的第一批测试。

## Out of Scope

- 真实医院数据的接入与映射脚本的具体实现（第一版只定义数据契约）。
- 组学模块的具体分析方法（第一版只预留接口与触发条件）。
- 中文文献源（知网、万方）的自动检索。
- 人工逐轮审批的交互模式（第一版全自动运行）。
- 多 agent 协作、长期记忆、跨运行的知识积累。
- 影像数据（眼表照片、睑板腺红外图等）的分析。
- Web 界面或多人协作功能（第一版用双击启动 + 中文菜单代替图形界面）。
